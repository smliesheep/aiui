## 5. 已知问题与后续

1. **冷缓存 AI 占比偏高**：首轮定位会走规则→AI；M5 采用“先预热一轮、再统计第二轮”的口径，同时用 `--sniff` 提高 hints 质量。
2. **截图只在失败/拦截时生成**：成功步骤默认不截图（`AIUI_SCREENSHOT_ON_SUCCESS=true` 可打开），控制证据体积。
3. **iframe 只支持单层**、shadow DOM 未支持：Virtual-Bank 前端不涉及，列入 roadmap。
4. **Fake 模式只能回放计划生成**：locate 回放需要与真实 DOM 候选编号绑定，单测用显式响应覆盖，CLI 离线演示只演示 `plan --fake`。
5. **API Key 已在对话中明文出现过**：验收后请到 DeepSeek 控制台轮换，并更新 `.env`（`.env` 已在 `.gitignore`）。

## 7. M4 之后的能力增强（为 M5 准备）

| 能力 | 命令 | 解决什么 | 实测 |
|---|---|---|---|
| 环境自检 | `aiui doctor` | 部署/换机时先确认驱动、key、allure、目录 | 8 项全 OK（chrome 157 + 本地 driver） |
| 计划体检 | `aiui lint <plan>` | 生成后先查 hints 质量、断言覆盖、高风险签核，不启动浏览器 | demo 计划 0 ERROR / 0 WARN |
| 多轮基准 | `aiui bench <plan> --rounds 3` | 把“冷缓存 → 暖缓存”收敛过程变成一张表，M5 取数不用手抄 | 冷 0/3/0 → 暖 3/0/0，0.75s → 0.57s |
| 批量回归 | `aiui suite "plans/demo_*.json"` | 8 条 E2E 一把跑完并汇总加权 AI 占比 | 2 计划 / 14 步全过，cache 11，AI 0% |
| 覆盖率 | `pytest --cov=aiui` | 量化“不是只测了个 happy path” | 核心 **83.3%**，全量 75.4% |

测试数从 79 增至 **98**（新增 doctor 6、lint 7、CLI 装配 6）。

> 说明：`aiui doctor` 会在启动浏览器后立刻 quit，不做任何页面操作；`bench`/`suite` 复用同一个浏览器会话以减少启动开销。
