## 1. 背景与目标

### 1.1 要做成什么

把「写 Selenium 脚本 → 调试 → 维护选择器」的传统 UI 自动化，改造成：

> **自然语言描述任务 → AI 澄清确认 → 自动执行 → 证据化报告**

框架接收一句话需求（如「用 admin 账号登录，给 11111111 转 100 USD，断言余额减少 100」），输出一份结构化、可评审、可执行的测试计划，并驱动浏览器完成操作、采集证据、生成 Allure 报告。

### 1.2 简历口径对齐（设计必须逐条落地）

| # | 简历描述 | 设计落点 | 验收方式（见 §11） |
|---|---|---|---|
| 1 | 将用户需求自动转换为结构化测试计划，Pydantic 校验动作参数、步骤顺序和风险等级，支持点击、输入、选择、断言、提取、截图等 10 类操作 | §5 数据契约 + §6.2 Planning 三层（Parser / Validator / Compiler） | 给出 20 条自然语言需求，≥18 条一次生成合法计划 |
| 2 | 构建「缓存优先—规则匹配—AI 兜底」三级定位机制，优先复用已验证定位器，规则无法唯一命中时才调用 AI；综合文本及业务上下文语义匹配；连续失效 3 次自动淘汰 | §6.3 LocatorResolver（Tier1/2/3 + 失效淘汰） | 全量回归中 AI 调用占比 ≤ 10%，缓存命中率 ≥ 60% |
| 3 | 限制大模型只能从程序采集的候选元素中返回目标编号与匹配置信度，置信度低于 0.6 或编号无效时拒绝执行 | §6.3.3 AI 兜底 + §6.2.2 后置校验（约束解码 + 枚举校验） | 构造 10 次"幻觉诱导"用例，0 次误点 |
| 4 | 大模型限制在意图理解、步骤规划、候选选择；不允许生成/执行任意代码；支付、删除、授权、发送消息、提交订单统一标高风险并在执行层拦截 | §6.5 Guardrail（风险分级 + 双语词表 + 执行层闸门） | 高风险负向用例 100% 被拦截且标记 BLOCKED |
| 5 | 集成 Allure，归档 6 类测试证据，失败自动保留非敏感页面现场，排查由"重新运行复现"转为"直接查看步骤及现场证据" | §6.6 Evidence + §6.7 Reporting | 失败用例报告中 6 类证据齐全，可从报告直接定位失败步骤 |

### 1.3 量化目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 单条用例从需求到可执行计划的耗时 | < 30s（含 1 次 LLM 调用） | 传统写法约 30-60min |
| 回归场景中 AI 定位调用占比 | ≤ 10% | 三级定位生效后的稳态 |
| 定位缓存命中率 | ≥ 60% | 同一 SUT 连续回归 |
| 计划一次生成合法率 | ≥ 90% | 经 Pydantic + 业务规则校验 |
| 失败用例平均定位耗时 | 由"重跑复现"降至"看报告" | 6 类证据支撑 |
| 框架自身单元测试覆盖率 | ≥ 80%（core/planning/locator/guardrail） | LLM 层用 Fake 网关 |

### 1.4 非目标（v1 明确不做）

- 不做移动端（App/小程序）自动化，仅 Web。
- 不做纯 API 测试编排（项目二已有 API 层；本项目保留 hook，v1 不实现 api/db 动作类型）。
- 不做用例管理系统/平台化前端（v1 以 CLI + 计划文件 + Allure 交付）。
- 不做模型微调，只用 Prompt + 约束解码 + 后置校验。
- 不做视觉识别定位（CV），元素定位仍走 DOM。

## 2. 名词约定

| 名词 | 含义 |
|---|---|
| Plan（测试计划） | 由自然语言生成的、Pydantic 校验通过的步骤序列，JSON 落盘、可评审、可版本化 |
| Step（步骤） | 计划中的单个动作，含 action / target / value / assertion / risk |
| Target（目标元素） | 用"自然语言描述 + 多源线索"表达的元素意图，**不是选择器** |
| Tier1/2/3 | 定位三级：缓存 / 规则 / AI 兜底 |
| Candidate（候选元素） | 程序从 DOM 采集的元素快照（带编号），是 AI 唯一可操作的对象 |
| Guardrail（护栏） | 执行层的高风险动作拦截与模型能力边界 |
| Evidence（证据） | 失败/成功时归档的 6 类现场材料 |

## 3. 总体架构

### 3.1 分层视图

```
┌──────────────────────────────────────────────────────────────────────┐
│ 输入层  自然语言需求 (CLI / pytest 用例 / plans/*.md)                  │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 规划层  RequirementParser(LLM) → PlanValidator(Pydantic+业务规则)     │
│         → ClarificationGate(澄清/确认) → PlanCompiler(动作白名单)      │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 执行层  Executor: 逐步执行 → ActionRegistry → LocatorResolver          │
│                  ├─ Tier1 Cache(SQLite)                                │
│                  ├─ Tier2 Rule(文本/属性/上下文打分)                    │
│                  └─ Tier3 AI(候选编号+置信度)                          │
│         Guardrail 在每步执行前做风险闸门                                │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 取证层  EvidenceCollector(6 类) → Allure Reporter → artifacts/run_id   │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 五道关卡（核心设计思想）

1. **结构化**：LLM 只输出 JSON，且 JSON 必须通过 Pydantic 模型 —— 不合法的计划进不了执行器。
2. **可澄清**：信息不足/存在歧义/涉及高风险时，先向人提问确认，不猜。
3. **白名单编译**：`ActionType` 枚举 → 已注册 Action 类，一对一映射；模型无法注入代码/表达式/脚本。
4. **执行层拦截**：风险判定不依赖模型自述，执行前由程序按动作类型 + 目标文本 + 值内容三重判定。
5. **证据闭环**：每个步骤无论成败都留着"为什么这么点、点了哪里、当时长什么样"。

### 3.3 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/运行时 | Python 3.10.8（已就绪） | 与项目二一致；环境已有 pydantic 2.12 / langchain-core 1.4 / openai 2.40 |
| 浏览器驱动 | Selenium 4.x + Selenium Manager | 免手工配 driver，本机已有 Chrome |
| 测试运行 | Pytest 7/8 + allure-pytest | 与项目二体系一致；Allure 原生步骤与附件 |
| LLM | DeepSeek（OpenAI 兼容协议，`deepseek-chat`） | 走 `langchain-openai.ChatOpenAI(base_url=...)`，便于换模型 |
| 数据校验 | Pydantic v2 | 模型校验 + JSON Schema 生成（约束解码用） |
| 缓存 | SQLite（标准库 sqlite3） | 零依赖、可随仓库分发、易观测 |
| 配置 | pydantic-settings + `.env` | 密钥不进代码/仓库 |
| 报告 | Allure 2 | 6 类证据附件、步骤树、失败信息 |
| CI | Jenkinsfile（可选实机） | 与项目二口径对齐 |

## 4. 关键流程

### 4.1 需求 → 计划（生成期）

```
用户: "登录后给 11111111 转 100 USD，断言余额减少"
  │
  ├─1. RequirementParser: 拼装 Prompt(需求 + 页面地图 + 动作白名单 + 输出Schema)
  │      → DeepSeek 返回 TestPlanDraft(JSON)
  ├─2. JSON 修复: 解析失败 / Schema 不符 → 带错误信息重问，最多 2 次
  ├─3. PlanValidator: Pydantic 类型校验 + 8 条业务规则(§6.2.2)
  ├─4. ClarificationGate:
  │      缺必填值(收款账号/金额)、目标描述歧义、含高风险动作 → 生成问题清单
  │      CLI 交互确认；CI 模式用 --yes 但高风险仍需 --allow-high-risk
  ├─5. PlanCompiler: 校验通过 → 编译为 ExecutableStep（注入等待、证据钩子、风险标签）
  └─6. 落盘 plans/<plan_id>.json + 指纹(plan_hash)，进入执行或等待人工评审
```

### 4.2 单步执行（运行期）

```
step = 下一步
  ├─ Guardrail.pre_check(step)           # 高风险 → BLOCKED，附"本应执行什么"
  ├─ Action = registry[step.action]      # 枚举→类，无动态代码
  ├─ if step.target:
  │     loc = LocatorResolver.resolve(target, context)
  │        Tier1 缓存: key=(page_key, target_sig) → 命中且 revalidate 通过 → 复用
  │        Tier2 规则: 对候选打分(exact>normalized>fuzzy)+上下文收敛 → 唯一命中
  │        Tier3 AI  : 采集候选(≤40) → 模型返回 {candidate_id, confidence} → 校验
  │     if loc is None → StepError(reason="low_confidence 0.42") → 证据
  ├─ Action.execute(loc, value)          # 显式等待 + 元素可交互性检查
  ├─ 断言/提取（如有）→ 记录 expected vs actual
  ├─ 成功 → 缓存写回(定位器 + 来源 + 置信度)
  └─ EvidenceCollector.attach(step)
```

### 4.3 失败排查（报告期）

失败步骤的 Allure 展示结构：

```
✗ Step 4 click 「确认转账」按钮                      [BLOCKED/TIMEOUT/...]
   定位链路: cache miss → rule ambiguous(2 candidates, gap=0.04) → ai(0.42 rejected < 0.60)
   候选元素: [12] button "确认" (visible) | [13] a "确认转账记录" (visible)
   模型响应: {"candidate_id": 13, "confidence": 0.42, "reason": "文本相近"}
   页面截图: step4_failure.png (full) / step4_element.png
   元素属性: <button class="btn-danger" ...> (truncated 1.2KB)
   文本提取: expected="转账成功" actual="转账失败：余额不足"
```

## 5. 数据契约（Pydantic 模型）

### 5.1 动作类型（10 类，白名单）

| ActionType | 语义 | 必填 | 产生证据 |
|---|---|---|---|
| `navigate` | 打开 URL | value=url | 页面截图 |
| `click` | 点击 | target | 元素属性 + 截图 |
| `input` | 输入文本 | target + value | 元素属性 |
| `select` | 下拉选择 | target + value | 元素属性 |
| `assert_text` | 断言文本包含/等于 | target 或 page + assertion | 文本提取 |
| `assert_element` | 断言元素存在/可见/可用 | target | 元素属性 |
| `extract` | 提取文本/属性到变量 | target + value=var_name | 文本提取 |
| `screenshot` | 主动截图（关键节点留档） | — | 页面截图 |
| `wait` | 等待元素/文本/固定毫秒 | target 或 value | — |
| `scroll` | 滚动到元素或页面位置 | target 或 value | — |

> 变量机制：`extract` 写入 `context.vars`，后续步骤可用 `${var}` 占位（如 `${balance_before}`），**仅支持变量替换，不支持表达式求值**（防注入）。

### 5.2 核心模型

```python
class RiskLevel(str, Enum):
    L0 = "L0"   # 只读（navigate/assert/extract/screenshot/wait/scroll）
    L1 = "L1"   # 可逆写（input/select）
    L2 = "L2"   # 业务写（点击提交类按钮）
    L3 = "L3"   # 高风险不可逆（支付/转账/删除/授权/发送/提交订单）

class TargetHints(BaseModel):
    text: str | None = None            # 可见文本
    label: str | None = None           # 表单 label
    placeholder: str | None = None
    aria_label: str | None = None
    role: str | None = None
    name: str | None = None
    test_id: str | None = None         # data-testid 优先
    nearby_text: str | None = None     # 邻近文本（"金额"输入框）
    container_text: str | None = None  # 所属区域（"转账表单"）

class TargetSpec(BaseModel):
    description: str = Field(min_length=2, max_length=200)  # 自然语言，如"转账金额输入框"
    hints: TargetHints = TargetHints()
    frame: str | None = None           # iframe 定位（v1 支持一层）

class Assertion(BaseModel):
    kind: Literal["contains", "equals", "regex", "exists", "visible", "enabled", "value"]
    expected: str | None = None

class PlanStep(BaseModel):
    id: str
    action: ActionType
    target: TargetSpec | None = None
    value: str | None = None
    assertion: Assertion | None = None
    timeout_ms: int = Field(default=8000, ge=500, le=60000)
    risk: RiskLevel = RiskLevel.L0
    intent: str = ""                   # 该步业务意图，进报告
    on_failure: Literal["abort", "continue", "retry"] = "abort"

class TestPlan(BaseModel):
    plan_id: str
    title: str
    requirement: str                    # 原始自然语言，原样归档
    base_url: str
    tags: list[str] = []
    preconditions: list[str] = []
    steps: list[PlanStep] = Field(min_length=1)
    approved_high_risk: list[str] = []  # 人工签核过的高风险 step id
    plan_hash: str = ""
```

### 5.3 定位结果模型

```python
class LocateResult(BaseModel):
    tier: Literal["cache", "rule", "ai"]
    locator: str                 # 最终 CSS/XPath（程序生成，非模型生成）
    candidate_id: int | None     # 仅 AI 档位
    confidence: float            # 0-1；cache 复用原置信度
    score: float = 0.0           # 规则档位打分
    reason: str = ""
    fallback_chain: list[str]    # ["cache:miss","rule:ambiguous(2)","ai:0.42"]
```

## 6. 模块设计

### 6.1 `llm/` —— 模型网关

**职责**：唯一与 DeepSeek 通信的出口；所有 Prompt、Schema、重试、审计集中在此。

| 组件 | 设计 |
|---|---|
| `gateway.py` | `ChatOpenAI(base_url="https://api.deepseek.com", model="deepseek-chat", temperature=0)`；统一超时（连接 10s / 读 60s）、指数退避重试（最多 2 次）、token 计量 |
| `schemas.py` | 由 Pydantic 模型导出 JSON Schema；定位环节额外注入 `candidate_id enum`，实现**约束解码** |
| `prompts/plan.txt` | 系统提示：角色、动作白名单、输出 Schema、禁止输出代码/选择器、未知信息标 `null` 并列入 `questions` |
| `prompts/locate.txt` | 只给候选元素清单（编号 + 标签 + 文本 + 位置），要求返回 `{candidate_id, confidence, reason}`，并声明"无法确定时返回 -1" |
| `cache.py` | `(prompt_hash, model)` → 响应缓存，命中即复用（离线演示/回归降本）；默认 TTL 7 天 |
| `audit.py` | 每次调用落盘 `artifacts/llm_calls/<run_id>.jsonl`：耗时、token、prompt 摘要、响应原文（脱敏）、校验结果 |

**成本控制**：候选元素上限 40 个、单元素描述 ≤ 120 字符、Prompt ≤ 6KB；计划生成每用例 1 次调用，定位只在 Tier3 触发。

**离线模式**：`AIUI_LLM=fake` 时用 `FakeGateway` 读取 `fixtures/llm/*.json`，保证 CI 无密钥可跑，也是框架自测的基础。

### 6.2 `planning/` —— 解析、校验、编译

#### 6.2.1 Parser

- 输入：需求文本 + 上下文（base_url、可用账号变量、上次成功计划作为 few-shot）。
- 输出：`TestPlanDraft`（Pydantic 宽松模型，允许 `null` 与 `questions`）。
- 失败修复：JSON 解析错误 / 必填缺失 → 把**具体错误**回灌重问（最多 2 次），仍失败则抛出 `PlanGenerationError` 并保留原始响应。

#### 6.2.2 Validator（8 条业务规则）

1. `steps` 非空；`step.id` 全局唯一。
2. 首个有效步骤必须是 `navigate`（或由 compiler 自动补）。
3. `action` ∈ 10 类枚举；未知动作 → 拒绝。
4. `input/select` 必须有 `value`；`assert_*` 必须有 `assertion`；`click/extract/scroll` 必须有 `target`（`scroll` 可只给 value）。
5. `base_url` 必须命中白名单域（防 SSRF / 误连生产）。
6. 步骤顺序合理性：`assert_*` 不得出现在首次 `navigate` 之前；`extract` 的变量必须被后续引用或至少定义在断言前。
7. 风险等级自洽：`declare` 的 risk 与动作类型不冲突（如 `assert_text` 标 L3 → 告警降级）。
8. 变量占位符 `${var}` 必须已定义（白名单变量 + 前序 extract）。

#### 6.2.3 ClarificationGate（"AI 澄清确认"）

触发条件：

| 触发 | 示例 | 交互 |
|---|---|---|
| 缺少执行必需数据 | 转账缺收款账号/金额 | 列出 1-3 个具体问题，等待回答后重生成（带答案） |
| 目标描述歧义 | "点击确认"（页面有 2 个确认） | 给出候选项让用户选，选定后写入 `hints` |
| 含 L3 高风险 | 转账/支付/删除 | 展示"将要执行的高风险动作清单"，需显式 `y` 或 `--allow-high-risk` + step id |
| 跨域跳转 | base_url 白名单外 | 拒绝，要求显式加白 |

CLI 交互式（默认）；CI 用 `--yes`，但 L3 仍需 `--allow-high-risk=<step_ids>`。

#### 6.2.4 Compiler

- 枚举 → Action 类（`registry[action]`）。
- 注入隐式等待（navigate 后等 `document.readyState`；click 前等元素 `visible & enabled & stable`）。
- 计算 `plan_hash`（规范化 JSON 的 sha256），用于报告关联与"计划变更即重评"。
- 变量表编译：`${VAR}` → 运行时替换，未定义直接编译期报错。

### 6.3 `locator/` —— 三级定位（核心）

#### 6.3.1 统一入口

```python
class LocatorResolver:
    def resolve(self, target: TargetSpec, ctx: RunContext) -> LocateResult:
        chain = []
        if (r := self._tier1_cache(target, ctx)): return r
        if (r := self._tier2_rule(target, ctx, chain)): return r
        return self._tier3_ai(target, ctx, chain)   # 可能抛 LowConfidenceError
```

#### 6.3.2 Tier1：缓存

- **键**：`sha256(page_key + "|" + target_signature)`
  - `page_key` = 路由模板（`/accounts/{id}`）+ 关键地标哈希（`<h1>`/`<form>` 的稳定文本，剔除动态数字）
  - `target_signature` = `description + hints 归一化`
- **值**：`locator(css/xpath)`、`source`(rule/ai)、`confidence`、`hit_count`、`fail_streak`、`last_verified_at`
- **复用条件**（revalidate，成本约 1 次 `find_elements`）：元素存在 && 可见 && 文本/属性与缓存期望一致；不一致 → 视为 miss 并降权。
- **失效淘汰**：`fail_streak >= 3` → `status=retired`，Tier1 跳过并记 warn，要求人工复核规则（对应简历"连续失效 3 次自动淘汰"）。
- **写回**：Tier2/Tier3 成功且步骤通过后写入（AI 档位保留 confidence，便于下次直接复用高置信定位）。

#### 6.3.3 Tier2：规则匹配（先规则、后模型）

- **候选集**：`collector.collect(driver, scope)` —— 可见、可交互元素（`a/button/input/select/textarea/[role]/[onclick]/label`），去重、限制 200 个。
- **单元素打分**（0-1，加权）：
  - `data-testid` 精确命中：+0.40
  - `name/id` 归一化命中：+0.30
  - `label` / `placeholder` / `aria-label` 归一化相等：+0.35，包含：+0.25
  - 可见文本相等：+0.35，包含：+0.25
  - `nearby_text` 出现在祖先容器（≤3 层）：+0.15
  - `container_text` 命中祖先容器：+0.10
  - 模糊相似度（`difflib.SequenceMatcher`）：`ratio × 0.20`
  - 可见性/可用性惩罚：不可见 -0.5
- **唯一命中判定**：`best.score >= 0.70` 且 `best.score - second.score >= 0.15` → 采用；否则判为 ambiguous，进入 Tier3（**只有规则无法唯一命中才调用 AI**）。
- **"语义匹配"落地**：文本归一化（全半角、大小写、去空白、去标点、同义词表如 登录/login/sign in、余额/balance），并叠加业务上下文（所属表单/抽屉/弹窗）收敛候选。

#### 6.3.4 Tier3：AI 兜底（防幻觉核心）

**候选采集**（程序负责，非模型）：每个元素给紧凑描述

```json
{"i": 12, "tag": "button", "role": "button", "text": "确认转账",
 "attrs": {"name": "confirm", "class": "btn btn-primary"},
 "box": [820, 460, 96, 32], "visible": true, "enabled": true}
```

**模型约束**：

- Prompt 只含：任务上下文（步骤 intent、目标 description、hints）、候选列表、输出 Schema。
- 输出 Schema 中 `candidate_id` 为 **enum（候选编号集合）**，`confidence` 为 0-1 数字，`reason` ≤ 60 字。
- `temperature=0`、`max_tokens=120`、`response_format=json_object`。

**后置校验（缺一不可）**：

1. `candidate_id` 必须在候选集合内（枚举本身已保证，仍做防御性检查）。
2. `confidence >= 0.60`，否则 `LowConfidenceError`（**拒绝执行，不猜**）。
3. 目标元素必须 `visible && enabled`（不满足则回退次优候选，最多 2 个）。
4. `reason` 非空，且与目标 description 无矛盾（宽松校验，仅记录）。

**日志**：无论接受/拒绝，都把 `候选片段 + 模型响应 + 判定结果` 写入定位证据（对应简历"定位器来源及置信度"）。

#### 6.3.5 指标

`RunSummary` 记录：`cache_hit / rule_hit / ai_hit / ai_rejected / retired`，以及平均定位耗时、AI 调用 token。回归结束打印，作为"AI 调用占比 ≤ 10%"的验收依据。

### 6.4 `actions/` —— 动作实现

- `base.py`：`BaseAction`（`precheck`/`execute`/`postcheck`/`evidence` 四段式）。
- `registry.py`：`dict[ActionType, type[BaseAction]]`，**静态注册**，禁止运行时反射/动态导入模型输出。
- 通用能力：显式等待（`WebDriverWait` + 自定义 expected_conditions）、元素滚动入视口、`stale element` 重取（最多 3 次）、点击被遮挡时降级 `JS click`（仅限非高风险动作，且记 warn）。
- 断言动作产出结构化 diff（expected/actual/path），供报告与证据使用。

### 6.5 `guardrail/` —— 安全与幻觉控制

#### 6.5.1 能力边界（模型不能做什么）

| 限制 | 实现 |
|---|---|
| 不能生成/执行任意代码 | 无 `execute_script` 暴露给模型；模型输出只能是枚举动作 + 字段 |
| 不能生成选择器 | 定位由程序完成；模型只回编号 |
| 不能写 SQL / 表达式 | 变量仅支持 `${var}` 字面替换，无 eval |
| 不能跨域 | base_url 白名单 + 跳转后同源校验 |
| 不能接触密钥 | 凭据由 `RunContext` 注入，Prompt 中只出现 `${USER}` 占位 |

#### 6.5.2 高风险判定（三重，任一命中即 L3）

1. **动作语义**：`click` 且目标是提交类（表单 submit / `type=submit`）。
2. **目标文本词表**（中英双语）：
   - 支付/付款/转账/汇款/提现/充值 → pay/payment/pay now/transfer/remit/withdraw/top up
   - 删除/注销/解绑/清空 → delete/remove/unbind/deactivate/clear
   - 授权/授权登录/同意协议/开通 → authorize/grant/consent/activate
   - 发送/发送消息/发邮件/通知 → send/send message/notify
   - 提交订单/下单/确认支付/购买 → submit order/place order/checkout/buy/confirm payment
3. **值内容**：`input` 的值命中金额/账号模式且目标含"转账/支付"语义 → 升级 L3。

#### 6.5.3 拦截点与表现

- 位置：`Guardrail.pre_check(step)` 在**动作执行前**，与模型自述的 risk 无关（模型标的低风险不采信，程序判定优先）。
- 表现：抛 `HighRiskBlocked`，步骤状态 `BLOCKED`（**不是 FAILED**，报告中单列），附"本应执行的动作 + 命中的规则"。
- 放行：仅当 `step.id ∈ plan.approved_high_risk` 且运行时 `--allow-high-risk` 开启；两者缺一即拦截。
- 负向用例：`tests/test_guardrail.py` 覆盖 12 组中英文高风险文本，要求 100% 拦截、0 误放。

### 6.6 `evidence/` —— 6 类证据

| # | 证据 | 内容 | 时机 |
|---|---|---|---|
| 1 | 任务归档 | 原始需求、计划 JSON、plan_hash、模型名、Prompt 版本 | 运行开始 |
| 2 | 执行计划 | 编译后步骤表（含解析出的 locator、耗时、状态） | 每步结束 |
| 3 | 定位来源与置信度 | tier、score、候选 vs 选中、AI confidence、fallback_chain | 每步定位 |
| 4 | 文本提取结果 | extract/assert 的 expected/actual/diff | 断言步 |
| 5 | 元素属性 | outerHTML(≤2KB)、bbox、可见/可用、关键属性 | 交互步 |
| 6 | 页面截图 | 全页 + 元素截图（失败时强制，成功时关键节点） | 失败/关键步 |

**脱敏**（`masking.py`）：password/otp/card/phone/id 类型输入、`input[type=password]`、`data-sensitive` 标记、Cookie/LocalStorage 一律不入证据；HTML 中疑似证件号/卡号正则替换为 `***`。

**体积控制**：单用例 artifacts ≤ 8MB；HTML 截断；截图 JPEG 质量 70；`artifacts/` 进 `.gitignore`。

### 6.7 `reporting/` —— Allure 集成

- 结构：`TestPlan` → `step` → 子步骤（定位/执行/断言/证据挂载），与计划步骤一一对应。
- 失败信息模板（可直接定位，不需重跑）：
  ```
  [STEP s4 click] 定位失败：三级链路 cache:miss → rule:ambiguous(2) → ai:rejected(0.42<0.60)
  目标：确认转账按钮 | 候选：[12] "确认" [13] "确认转账记录"
  ```
- 附件命名：`01-requirement.md`、`02-plan.json`、`03-locate.json`、`04-text.json`、`05-element.html`、`06-screenshot.png`。
- 环境信息：SUT 版本、浏览器版本、模型、框架版本写入 Allure environment。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LLM 输出不稳定/幻觉 | 计划非法、误点 | 约束解码 + Pydantic + 业务规则 + 置信度阈值 + 计划落盘可评审 |
| 动态 DOM / iframe / shadow DOM | 定位失败 | 候选采集加稳定等待、去动态文本；v1 支持单层 iframe，shadow DOM 列入 roadmap |
| 缓存脏数据（页面改版） | 点错元素 | revalidate + fail_streak 淘汰 + 缓存带 TTL |
| Token 成本/延迟 | 回归变慢 | 三级定位、候选裁剪、响应缓存、Fake 模式 |
| 高风险误放行 | 业务事故 | 程序侧三重判定（不采信模型 risk）+ 双开关放行 + 负向用例 |
| SUT 不可用（Docker/网络） | 阶段 5 阻塞 | 方案 C 兜底；框架本身不依赖 SUT |
| 密钥泄露 | 安全事故 | `.env` + 日志脱敏 + 证据脱敏 + 报告不含凭据 |
| Windows 环境差异 | 启动失败 | Selenium Manager 自动驱动；路径统一 pathlib；PowerShell 脚本封装 |
