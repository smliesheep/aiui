## 1. 一分钟版本

> 我做了一个 AI 驱动的 UI 自动化测试框架：用一句中文需求生成可评审的 JSON 测试计划，
> 执行时按「缓存 → 规则 → 模型」三级定位，高风险动作由执行层拦截，失败自动留 6 类证据。
> 在真实项目 Virtual-Bank 上跑了 5 条 E2E、60 个步骤全通过，AI 调用占比 0%（暖缓存），
> 每步都能在 Allure 里看到定位链路和现场截图。

## 3. 被追问时的标准答法

**Q：AI 到底用了多少？是不是噱头？**
> 60 步里只有 1 步需要模型兜底（开户页那个 `placeholder="+"` 的输入框），暖缓存下 0 次。
> 模型只在两处出现：生成计划（每场景 1 次）和规则分不出高下时选编号。这是设计目标——AI 是兜底，不是主路径。

**Q：为什么不让模型直接写选择器？**
> 写选择器是幻觉重灾区，它编一个不存在的 XPath 你根本拦不住。我改成让它做选择题：程序采集候选、打编号，模型只回编号和置信度，再校三件事（编号存在、置信度≥0.6、元素可见可用）。

**Q：怎么保证不误点支付/删除？**
> 三重判定：动作类型、中英文风险词表、输入值是否金额+转账语义。判定不采信模型自报的风险等级。
> 拦截后状态是 BLOCKED 不是 FAILED，报告里单列，并写明"本应执行什么"。放行要计划签核 + 运行时 `--allow-high-risk` 两个开关。

**Q：8 条 E2E 为什么只做了 6 条？**（重点）
> 不是没写，是这个开源 SUT 用户端没有借记卡功能：`DebitCardList` 权限是 `IsAdminUser`，用户端只有 list/retrieve，`debit_cards/urls.py` 是空的；卡是开 CURRENT 账户时后端自动建的。
> 支付只有 `/debit-cards/payment/` 接口、没有页面。我已经把 UI 能覆盖的 6 条全跑通了，剩下 2 条作为被测系统的能力边界记录，并保留了这个证据（代码 + 接口实测）。

**Q：这套东西在真实页面改动后还能用吗？**
> 缓存复用前会 revalidate（元素在不在、可见不可见、文本对不对）；失败累计 3 次自动 retire，强制重新发现。这次测 Virtual-Bank 就踩到过：改了浏览器侧 API 地址后，E2/E3 从失败转通过，定位链路在报告里能直接看到。

**Q：测试本身发现了什么？**
> 四个问题：浏览器侧 `API_BASE_URL` 指向容器主机名导致转账/开户请求根本不发出；`chart.js` 空引用报错；Postgres 5432 与本机冲突；注册表单 `date_of_birth` 必填但表单没有显式提示，被 HTML5 静态校验拦住（表现为"点了没反应"）。

**Q：怎么证明不是只测了 happy path？**
> 框架自身 98 条用例，核心模块覆盖率 83.3%；12 组中英高风险词 100% 拦截；防幻觉用例覆盖越界编号、低置信、非法 JSON；E8 是未登录权限负向场景。

## 4. 演示顺序（5 分钟）

1. `aiui doctor` —— 环境自检（驱动/key/allure）；
2. `aiui plan "..." --sniff` —— 现场生成计划，指出"这是 JSON，人可以 review"；
3. `aiui lint` + `aiui approve` —— 体检 + 签核高风险；
4. `aiui run` 或 `pytest` —— 跑一条转账，翻 Allure 的定位链路；
5. 打开 `artifacts/<run>/steps/s9/03-locate.json` —— 展示 `cache:miss → rule:low_score → ai:accept(0.95)`。

## 5. 不要说的话

- 不要说"AI 自动理解页面"——它只做选择题，页面理解靠规则和候选采集；
- 不要说"8 条全过"——说 6/8，并给出 SUT 能力边界证据，反而加分；
- 不要说"零维护"——说"维护成本下降，页面改版靠 retire 机制重新学习"。
