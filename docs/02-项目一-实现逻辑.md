## 1. 一句话概括实现逻辑

> 把「自然语言」编译成「一个只含 10 种动作的 JSON 计划」，再由一个**不信任模型的执行器**逐步执行；
> 每一步执行前先过风险闸门，执行时按「缓存→规则→AI」三级找元素，执行后把 6 类现场证据挂到 Allure 上。

四个"不信任模型"的具体体现：

| 不信任点 | 兜底手段 |
|---|---|
| 模型可能输出非法结构 | Pydantic + 8 条业务规则 + 修复重问（≤2 次） |
| 模型可能编造元素 | 元素只能从程序采集的候选里**选编号**，且置信度 < 0.6 直接拒绝 |
| 模型可能输出代码/选择器 | 动作是枚举→类的一对一映射，选择器由程序生成，没有 eval 通道 |
| 模型可能低估风险 | 风险由程序按「动作类型 + 目标文本 + 输入值」三重判定，不采信模型自报 |

| 对象 | 谁产生 | 谁消费 | 内容 |

### 3.2 计划生成 `planning/parser.py`（约 130 行）

**Prompt 组装**（4 段，总长 ≤ 6KB）：

```
[系统] 你是 UI 测试计划生成器。只能输出 json。动作白名单：navigate/click/input/...
       禁止输出选择器、代码、SQL。信息不足时把问题写进 questions，字段填 null。
[上下文] base_url、可用变量(${USER}/${PASS})、页面地图(可选 --sniff 采集，≤2KB)
[示例] 2 个 few-shot（登录、转账），含完整 JSON
[任务] 需求原文
```

**调用与修复循环**：

```python
def parse(requirement, ctx) -> TestPlanDraft:
    messages = build_messages(requirement, ctx)
    for attempt in range(3):                       # 1 次生成 + 最多 2 次修复
        raw = gateway.chat_json(messages)          # json_object 模式
        try:
            draft = TestPlanDraft.model_validate(raw)
            return draft
        except ValidationError as e:
            messages += [
                {"role": "assistant", "content": raw},
                {"role": "user", "content":
                 f"上面的 json 不合法，请只修正这些错误后重新输出完整 json：\n{e.errors()[:5]}"},
            ]
    raise PlanGenerationError(raw, messages)
```

> 关键点：**把 Pydantic 的 errors 原文回灌**，比"再试一次"有效得多；同时限制 3 次，防止 token 烧穿。

**可选 `--sniff` 页面地图**：先起一个 headless 浏览器打开 base_url，采集
`forms[{label, inputs[{label,type,name}]}], buttons[{text,type}], links[≤10], headings`
压成 ≤2KB JSON 塞进上下文 —— 让模型生成的 `hints` 有真实依据，Tier2 命中率显著提高。

### 3.3 校验 `planning/validator.py`（约 120 行）

校验器不是"再跑一遍 Pydantic"，而是**业务合理性**。实现为规则列表，每条返回 `Violation(step_id, rule, message)`：

```python
RULES = [
    r_no_empty_steps,        # 1 steps 非空、id 唯一
    r_navigate_first,        # 2 首个有效步必须是 navigate（否则 compiler 补）
    r_action_whitelist,      # 3 action ∈ 枚举（Pydantic 已保证，防御性再查）
    r_required_fields,       # 4 input/select 要 value；assert 要 assertion；click 要 target
    r_host_allowlist,        # 5 base_url 命中白名单
    r_order_sanity,          # 6 assert 不能早于 navigate；extract 变量需先定义后使用
    r_risk_consistency,      # 7 动作语义与声明风险冲突 → 自动升级并 warn
    r_variables_defined,     # 8 ${var} 必须在 whitelist ∪ 前序 extract 中
]
```

`r_order_sanity` 的实现要点：维护一个 `defined_vars` 集合，顺序扫描 `steps`，遇 `extract` 加入，遇 `${x}` 检查是否在集合里 —— 这是**编译期**发现的错误，不用等到浏览器里才炸。

### 3.4 澄清 `planning/clarify.py`（约 70 行）

```python
def gate(plan, settings, interactive) -> TestPlan:
    questions = collect_questions(plan)      # 缺值 / 歧义 / L3 未签核
    if not questions:
        return plan
    if not interactive:
        raise ClarificationRequired(questions)   # CI 模式：直接失败并打印问题清单
    for q in questions:                       # 逐条问，答案回填再重编译
        answer = prompt_user(q)
        plan = apply_answer(plan, q, answer)
    return plan
```

问题类型固定 3 种，避免开放式提问：

| 类型 | 生成方式 | 答案回填 |
|---|---|---|
| `missing_value` | 扫描 `input` 的 value 为 null/`${UNDEFINED}` | 写入 step.value |
| `ambiguous_target` | 生成期标注 `needs_confirm=true` | 写入 `target.hints` |
| `high_risk_confirm` | 风险判定为 L3 | 写入 `approved_high_risk[]` |

### 3.5 编译 `planning/compiler.py`（约 90 行）

```python
def compile(plan: TestPlan) -> list[ExecutableStep]:
    out = []
    for s in plan.steps:
        cls = ACTION_REGISTRY[s.action]       # 静态字典，KeyError 即拒绝
        out.append(ExecutableStep(
            step=s, action_cls=cls,
            wait_ms=s.timeout_ms or settings.timeout_ms,
            risk=policy.classify(s),          # 程序判定，覆盖模型自报
            var_refs=scan_vars(s),            # ${x} 列表
        ))
    plan.plan_hash = sha256(canonical_json(plan))
    return out
```

**编译期做掉的 3 件事**：① 枚举→类映射（无反射、无动态 import）；② 风险重判（`policy.classify`）；③ 变量依赖表（执行期 O(1) 查）。

### 3.6 执行主循环 `executor/runner.py`（约 150 行）

```python
def run(plan, ctx) -> RunSummary:
    steps = compile(plan)
    with allure.step(plan.title):
        for es in steps:
            s = es.step
            with allure.step(f"{s.id} {s.action} {s.target.description if s.target else ''}"):
                try:
                    ctx.guard.pre_check(es)                      # ① 闸门
                    loc = ctx.resolver.resolve(s.target, ctx) if s.target else None  # ② 定位
                    ctx.actions[es.action_cls].execute(ctx, es, loc)                  # ③ 执行
                    ctx.evidence.attach_step(es, loc, status="passed")                 # ④ 取证
                    if loc: ctx.cache.confirm(loc, page_key=ctx.page_key())            # ⑤ 回写
                except HighRiskBlocked as e:
                    ctx.evidence.attach_blocked(es, e)
                    return ctx.finish("blocked", es)             # 立即停，不继续造数据
                except (LocateError, StepTimeout) as e:
                    ctx.evidence.attach_step(es, loc, status="failed", error=e)
                    if not ctx.retry_policy.allow(es): return ctx.finish("failed", es)
                    ctx.retry_policy.backoff()
                    # 重试时强制跳过 Tier1（可能是脏缓存）
                    ctx.force_tier = "rule"
    return ctx.finish("passed")
```

**重试策略（显式，不靠 pytest-rerunfailures）**：

| 失败类型 | 重试 | 特殊处理 |
|---|---|---|
| `LowConfidenceError` | 不重试 | 直接失败，报告写清"模型不确定"，避免瞎点 |
| `StepTimeout` / `StaleElement` | 1 次 | 重试前 `refresh` 页面并跳过 Tier1 缓存 |
| `AmbiguousError` | 1 次 | 重新采集候选（DOM 可能已变） |
| `HighRiskBlocked` | 0 | 立即终止整个计划 |

### 3.7 候选采集 `locator/collector.py`（约 120 行，全框架最关键的一段）

**为什么要"程序采集 + 模型选编号"**：如果让模型直接写 CSS/XPath，它 90% 会编出不存在的选择器；而"从 40 个真实元素里挑一个编号"是分类任务，模型几乎不会错。

实现方式：一段注入 JS，给每个候选元素**打临时标记**，这样后续能用稳定 CSS 定位它：

```javascript
// 伪代码：collect.js
const SEL = 'a,button,input,select,textarea,[role=button],[role=link],[onclick],label';
const nodes = [...document.querySelectorAll(SEL)];
return nodes.filter(visible).slice(0, 200).map((el, i) => {
  el.setAttribute('data-aiui-id', i);                 // ← 关键：打标
  return {
    i,
    tag: el.tagName.toLowerCase(),
    role: el.getAttribute('role') || '',
    text: (el.innerText || el.value || '').trim().slice(0, 60),
    attrs: {name: el.name, id: el.id, ph: el.placeholder,
            aria: el.getAttribute('aria-label'),
            testid: el.dataset.testid, type: el.type,
            cls: (el.className || '').toString().slice(0, 40)},
    box: [rect.x, rect.y, rect.width, rect.height],
    visible: isVisible(el), enabled: !el.disabled
  };
});
```

Python 侧拿到后：

1. 过滤不可见/不可用（除 `assert_element` 需要保留）。
2. 计算 `page_key`（路由模板 + 地标文本哈希），供缓存用。
3. 候选列表同时喂给 **Tier2 规则**和 **Tier3 模型** —— 一次采集，两处复用，避免重复 DOM 分析（对应"减少重复 DOM 分析"）。
4. 定位成功后用 `[data-aiui-id="12"]` 拿元素；操作前清除标记（`finally` 里清理），避免污染页面断言。

> 坑：React/Vue 重渲染会把 `data-aiui-id` 弄丢 → `resolve` 失败时**重新采集一次**再试（最多 2 次），这是必要的容错。

### 3.8 三级定位 `locator/*`（约 410 行，核心）

#### 3.8.1 入口 `resolver.py`

```python
def resolve(self, target, ctx) -> LocateResult:
    chain = []
    pk = ctx.page_key()

    # Tier1 缓存
    if ctx.force_tier != "rule":
        hit = self.cache.get(pk, sig(target))
        if hit and self.cache.revalidate(ctx.driver, hit):        # 1 次 find_elements 校验
            return LocateResult(tier="cache", confidence=hit.confidence,
                                locator=hit.locator, fallback_chain=chain + ["cache:hit"])

    cands = self.collector.collect(ctx.driver, target)            # 一次采集，两级共用

    # Tier2 规则
    best, second = self.rules.rank(target, cands)
    if best and best.score >= 0.70 and (best.score - second.score) >= 0.15:
        return LocateResult(tier="rule", locator=css(best.i), score=best.score,
                            confidence=best.score, fallback_chain=chain + ["rule:hit"])

    # Tier3 AI
    return self.ai.match(target, cands, ctx, chain + [f"rule:ambiguous({best and best.score:.2f})"])
```

#### 3.8.2 Tier2 打分 `rules.py`（可解释、可调参）

```python
W = {"testid": .40, "attr_exact": .30, "label_eq": .35, "label_in": .25,
     "text_eq": .35, "text_in": .25, "nearby": .15, "container": .10, "fuzzy": .20}

def score(target, c) -> float:
    s, h = 0.0, target.hints
    if h.test_id and c.attrs["testid"] == h.test_id: s += W["testid"]
    if h.name and norm(h.name) == norm(c.attrs["name"]): s += W["attr_exact"]
    for key, attr in (("label","label"), ("placeholder","ph"), ("aria_label","aria")):
        hv = getattr(h, key)
        if hv:
            s += W["label_eq"] if norm(hv) == norm(c.attrs[attr]) else \
                 W["label_in"] if norm(hv) in norm(c.attrs[attr]) else 0
    if h.text: s += W["text_eq"] if norm(h.text) == norm(c.text) else W["text_in"] if norm(h.text) in norm(c.text) else 0
    if h.nearby_text and h.nearby_text in ancestors_text(c, depth=3): s += W["nearby"]
    if h.container_text and h.container_text in ancestors_text(c, depth=6): s += W["container"]
    s += W["fuzzy"] * SequenceMatcher(None, norm(h.text or target.description), norm(c.text)).ratio()
    if not c.visible: s -= 0.5
    return max(s, 0.0)
```

**语义归一化 `norm()`**：全半角统一 → 小写 → 去空白/标点 → 同义词替换（`登录/login/sign in`、`余额/balance/可用余额`、`确认/确定/confirm`）。这是"综合文本及业务上下文语义匹配"的落地点。

**为什么卡 0.70 / 0.15 双阈值**：只卡绝对分会导致"两个都 0.65 → 随便选一个"；卡 gap 才能识别"页面有两个几乎一样的按钮"这种真实歧义，交给 AI 或交给人。

#### 3.8.3 Tier3 模型选择 `ai_matcher.py`

请求体（候选先裁剪，控制 token）：

```json
// 只给模型看这些，且候选 < 40 个
{"task": "在转账表单里找到提交按钮",
 "hints": {"text": "确认转账", "container_text": "转账"},
 "candidates": [
   {"i": 12, "tag": "button", "text": "确认转账", "attrs": {"cls": "btn btn-primary"}},
   {"i": 13, "tag": "a",      "text": "确认转账记录"}
 ]}
```

系统提示（硬约束）：

```
只能从 candidates 的编号中选一个。输出 json：{"candidate_id": <编号>, "confidence": 0~1, "reason": "<60字"}
不确定就 candidate_id = -1, confidence = 0。禁止输出选择器、XPath、代码。
```

后置校验（**任何一条不过就拒绝，不降级猜测**）：

```python
r = json.loads(raw)
cid = r.get("candidate_id", -1)
if cid not in {c.i for c in cands}:          raise LowConfidenceError("invalid_id", chain)
if float(r.get("confidence", 0)) < 0.60:     raise LowConfidenceError(f"low_conf={r['confidence']}", chain)
el = by_marker(cid)
if not (visible(el) and enabled(el)):        # 次优候选重试 ≤2 个
    ...
return LocateResult(tier="ai", locator=f'[data-aiui-id="{cid}"]',
                    candidate_id=cid, confidence=conf, reason=r["reason"], fallback_chain=chain)
```

> 这里体现简历第 3 条：**模型只能返回编号和置信度**，编号无效或置信度 < 0.6 → 拒绝执行。日志把"候选 + 响应 + 判定"三件套存下来，面试可直接展示。

**淘汰（对应简历"连续失效 3 次自动淘汰"）**：

```python
def on_fail(self, key):
    self.db.execute("UPDATE locator SET fail_streak=fail_streak+1 WHERE key=?", (key,))
    row = self.get_by_key(key)
    if row.fail_streak >= 3:
        self.db.execute("UPDATE locator SET status='retired' WHERE key=?", (key,))

```

> 淘汰 ≠ 删除：保留记录用于复盘，但 Tier1 不再使用，强制走规则/AI 重新发现。

### 3.9 动作 `actions/`（约 400 行）

统一四段式，保证"每个动作都自动产生证据"：

```python
class BaseAction:
    def execute(self, ctx, es, loc):
        self.precheck(ctx, es, loc)      # 元素可见/可用、页面就绪
        self.perform(ctx, es, loc)       # 真正的 click/send_keys/select
        self.postcheck(ctx, es, loc)     # 断言/提取/值回读
        self.collect(ctx, es, loc)       # 元素属性 + 截图
```

| 动作 | 实现要点 |
|---|---|
| `click` | `scrollIntoView` → 等 `stable`（bbox 连续 2 帧不变）→ 原生 click；被遮挡才降级 JS click 并记 warn |
| `input` | `clear()` 后 `send_keys`；读回 value 校验是否被前端格式化（金额 `1,000.00`） |
| `select` | `Select(...).select_by_visible_text`，失败回退 value |
| `assert_text` | 取 `innerText`，按 `contains/equals/regex` 比对，产出 `{expected, actual, path}` |
| `extract` | 支持 `innerText/value/@attr`，写入 `ctx.vars[name]`（供 `${var}` 用） |
| `wait` | 优先"等待条件"（元素出现/文本变化），不用死 sleep |
| `screenshot` | 全页 + 元素两档，命名 `step{id}_{name}.png` |

### 3.10 护栏 `guardrail/policy.py`（约 100 行）

```python
HIGH_RISK_WORDS = {
  "payment":  ["支付","付款","转账","汇款","提现","充值","pay","payment","transfer","withdraw","top up"],
  "delete":   ["删除","注销","解绑","清空","delete","remove","unbind","deactivate"],
  "auth":     ["授权","同意协议","开通","authorize","grant","consent","activate"],
  "send":     ["发送","发消息","发邮件","通知","send","notify"],
  "order":    ["提交订单","下单","确认支付","购买","checkout","place order","confirm payment"],
}

def classify(es) -> RiskLevel:
    t = (es.step.target.description if es.step.target else "") + (es.step.value or "")
    hit = [k for k, ws in HIGH_RISK_WORDS.items() if any(w in t.lower() for w in ws)]
    if hit and es.step.action in ("click", "input", "select"): return RiskLevel.L3
    if es.step.action == "click" and is_submit_target(es):     return RiskLevel.L3
    if es.step.action in ("input", "select"):                  return RiskLevel.L1
    return RiskLevel.L0

def pre_check(es, allow_high_risk):
    if es.risk is RiskLevel.L3 and not (
        es.step.id in allow_high_risk and es.step.id in es.plan.approved_high_risk):
        raise HighRiskBlocked(rule_hit=..., would_do=describe(es))
```

**双开关设计**：`--allow-high-risk=s7`（运行时）+ `plan.approved_high_risk=["s7"]`（计划签核过）。**两个都有才放行** —— 防止"跑一下 --allow-high-risk 把所有支付都放过去"。

## 5. 关键算法细节汇总

| 算法 | 参数 | 位置 |
|---|---|---|
| 规则唯一命中 | `best ≥ 0.70` 且 `best - second ≥ 0.15` | `rules.rank` |
| AI 接受阈值 | `confidence ≥ 0.60` 且 `id ∈ 候选` 且元素可见可用 | `ai_matcher.match` |
| 定位淘汰 | `fail_streak ≥ 3` → `status=retired` | `cache.on_fail` |
| 缓存键 | `sha256(route_template + landmark_hash + "\|" + norm(description+hints))` | `cache.key` |
| 路由模板 | 数字/UUID 段替换为 `{id}`，如 `/accounts/123` → `/accounts/{id}` | `collector.page_key` |
| 计划指纹 | `sha256(canonical_json(plan))`，计划一改指纹就变 | `compiler` |
| 重试预算 | 超时/Stale 1 次、歧义 1 次、低置信 0 次、拦截 0 次 | `executor.retry` |
| 证据体积 | 单用例 ≤ 8MB，HTML ≤ 2KB，截图 JPEG q70 | `evidence` |

## 7. 已知坑与应对（实现时直接按这个做）

| 坑 | 现象 | 应对 |
|---|---|---|
| DeepSeek `json_object` 要求 prompt 里出现 "json" 字样 | 400 报错 | 系统提示固定首句含 `只输出 json` |
| `response_format` 不做 schema 强约束 | 字段缺失/类型错 | 视作"伪约束解码"：Prompt 注入 Schema + 枚举 + Pydantic 后置 + 修复重问 |
| Windows 控制台 GBK | 中文乱码/`UnicodeEncodeError` | 全程 `encoding="utf-8"`，入口设 `PYTHONUTF8=1`，日志用 UTF-8 handler（本次已实测 API 返回 UTF-8 正常） |
| Selenium Manager 首次下载 driver | 首次启动慢/无网失败 | 首次运行单独跑一次预热；失败给出明确提示与手动 driver 路径配置 |
| React 重渲染丢 `data-aiui-id` | 定位到 stale | 重新采集 1 次再定位 |
| 两个同名按钮 | 规则误点 | gap 阈值 → 判歧义 → Tier3 或澄清 |
| 金额被前端格式化 | 输入后断言失败 | input 后回读 value，按 `,` 归一化再断言 |
| Allure 只有 json 没有 html | 打不开报告 | 提供 `aiui report`（`allure generate`），README 写明需 allure CLI |
| 缓存键含 URL 数字 id | 命中率接近 0 | 路由模板归一化 |
| 证据把密码截进截图 | 安全事故 | 截图前对 `input[type=password]` 打码（`-webkit-text-security`）或遮罩区域 |
